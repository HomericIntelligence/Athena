# P004 — SOLID

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- Each module has one primary responsibility and one cause of change.
- A stable component has an extension path for needed variation, not for imagined variation.
- A subtype keeps the observable behavior of its abstraction.
- Clients depend only on the capabilities they use.
- High-level policy depends on stable contracts, not on details that change.
- Classes and interfaces are not required. The ideas apply to functions and data too.
- SOLID names are not a reason to add indirection with no current purpose.

## Limits

No result is rejected because compliance cannot be shown.
