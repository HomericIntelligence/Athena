# P091 — Test-Driven Development

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- The author writes one failing test for the next necessary behavior before the change.
- The author makes the test pass with the smallest correct production change.
- The author refactors while the suite continues to pass.
- The author records the expected failure before the fix, so the Red step is real.
- The author keeps verification wider than the TDD cycle: builds, types, lint, and integration checks also matter.

## Limits

No output is rejected because compliance cannot be shown. Credential and PII protection still applies.
