# P008 — Understand Before Subtracting

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- Before a deletion, time is spent finding consumers, contracts, and history.
- Tests and documentation are read for what they say about the mechanism.
- Version history and issue context are checked for compatibility or failure lessons.
- Security, migration, and operation roles that quiet code paths hide are looked for.
- Local, isolated mechanisms with no found consumers can get a light check.
- History informs the decision; it does not freeze an obsolete design in place.

## Limits

No result is rejected because compliance cannot be shown.
