# P063 — Requirement-to-Code Traceability

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- Each important change traces to a requirement, acceptance criterion, defect, invariant, or
  necessary dependency.
- Trace links stay lightweight. A large traceability matrix is not the goal.
- The requirement and acceptance criteria are stated before implementation.
- Each change is narrow and its rationale is clear in the issue, plan, or pull-request
  description.
- Important design and code decisions map to their requirements.
- Support changes, such as migrations and compatibility work, are recorded as dependencies.
- Trace links are updated when requirements or ownership change.

## Limits

No output is rejected because compliance cannot be shown. Credential and PII protection still applies.
