# P048 — Secure by Design

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- Assets, actors, and trust boundaries are recorded before a capability changes trust.
- Threats, failure modes, and controls are found early, before the cost of change rises.
- Controls fit the assets, threats, and impact. Maximum controls everywhere are not the goal.
- Validation, isolation, and authorization are selected before implementation details.
- Security tests, update paths, and incident response are part of delivery planning.
- The threat model is revisited when permissions, integrations, or assumptions change.
- Security outcomes stay with the product, not only with the user.

## Limits

No output is rejected because compliance cannot be shown. Credential and PII protection still applies.
