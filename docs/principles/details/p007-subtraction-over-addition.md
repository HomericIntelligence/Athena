# P007 — Subtraction Over Addition

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- Removal, consolidation, and reuse are considered before new code, state, or dependencies.
- Obsolete branches, duplicate state, and spare capabilities get a second look.
- When an existing mechanism does the job, that mechanism is preferred.
- Total lifecycle, failure, and security costs are weighed, not only build effort.
- Subtraction is a prompt to think, not a reason to remove needed controls.
- An existing mechanism is kept when it carries a needed behavior or protection.

## Limits

No result is rejected because compliance cannot be shown.
