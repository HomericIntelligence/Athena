# P064 — Requirement-to-Test Traceability

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- Each behavior change gets verification tied to its requirement, acceptance criterion, defect,
  or invariant.
- Verification can be a test, property check, integration check, static analysis, or another
  risk-based method.
- The lowest-cost test level that proves the contract is preferred.
- Acceptance criteria and invariants are turned into observable verification targets.
- Failure paths, boundaries, and representative success cases are checked.
- A test proves evidence only when a defect can make it fail.
- Requirement and test are updated together when the accepted contract changes.

## Limits

No output is rejected because compliance cannot be shown. Credential and PII protection still applies.
