# P021 — Evolutionary and Reversible Design

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- Change arrives in small, behavior-preserving steps instead of one big rewrite.
- Each merged state keeps the system working.
- A way back, or a way forward to safety, is kept until the new state proves itself in operation.
- Additive schema changes, adapters, and feature controls ease risky transitions.
- Irreversible steps are found and moved as late as possible in the sequence.
- Some actions cannot be reversed; those are chosen deliberately and with care.

## Limits

No result is rejected because compliance cannot be shown.
