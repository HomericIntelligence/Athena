# P012 — Evidence Before Modification

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- Before a change, the current behavior is read: code, callers, tests, contracts, and config.
- Repository instructions are read before local analysis begins.
- Narrow observations are gathered before a solution is chosen.
- Facts and inferences are kept separate.
- Unresolved questions are recorded; when in doubt, a small reversible experiment is tried.
- A local symptom is not treated as the whole design.
- Analysis stops when it is sufficient for the decision at hand.

## Limits

No result is rejected because compliance cannot be shown.
