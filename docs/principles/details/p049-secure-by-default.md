# P049 — Secure by Default

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- A new installation starts with the safer configuration.
- The easiest supported path gives useful protection without an activation step.
- Weaker modes need a clear and visible selection by the user.
- Endpoints, accounts, tools, and listeners that are not necessary stay disabled.
- Secure protocol, cryptographic, privacy, and update settings are the defaults.
- High-risk configuration changes are clear, visible, and reversible.
- Migration guidance helps installed systems adopt stronger defaults.

## Limits

No output is rejected because compliance cannot be shown. Credential and PII protection still applies.
