# P087 — Comments Explain Why, Code Explains What

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- The author makes code clear with names, structure, and types first.
- The author adds a comment when the code cannot show important rationale, limits, invariants, or tradeoffs.
- The author keeps comments adjacent to the behavior they explain.
- The author refers to the controlling specification, issue, or measurement when one exists.
- The author changes or removes comments in the same change that makes them incorrect.

## Limits

No output is rejected because compliance cannot be shown. Credential and PII protection still applies.
