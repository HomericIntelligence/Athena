# P015 — Architecture Conformance

This principle is a goal for engineering work. It does not authorize or block an action.

## What it looks like

- A change is placed in the component responsible for it.
- The change uses the established contracts, boundaries, and dependency direction.
- Adjacent patterns with the same purpose are followed.
- Architecture documentation is read before the change and checked against the code.
- An architecture change is made deliberately, with its own scope, when the current shape no longer fits.
- Obsolete architecture can be replaced by decision; it is not preserved only because it exists.

## Limits

No result is rejected because compliance cannot be shown.
